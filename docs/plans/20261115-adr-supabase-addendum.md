# ADR 0001 に Supabase を追記する

## Context

DB の候補として Supabase が挙がったので、無料枠、課金の仕組み、接続方法を調べて TiDB Cloud Starter と比べた。結論は、DB は TiDB Cloud Starter のままにする。ADR 0001 は「選ばなかった候補とその理由」を残すためのものなので、Supabase を追記する。DB もデプロイ先も変えないので、ロードマップと `GLOSSARY.md` は変更しない。

選ばなかった理由（2026 年 11 月時点）:
- Free プランは、DB へのアクセスが 1 週間ほどないとプロジェクトが一時停止される。この学習計画は 1 ステップずつ時間をかけて進め、「時間を置いてから書き直す」ルールもあるので、数週間あくと本番の DB が止まる
- 無料枠を超えても課金はされない（通知のあと、超過が続くと利用が制限される）。この点は TiDB と同じで、決め手にはならない
- Supabase の強み（認証、ストレージ、自動生成の REST API）は、API を Go で自作するこの計画では使わず、PostgreSQL を置く場所としてしか使えない
- Cloud Run からの直接接続は IPv6 だけで、IPv4 では共有プーラー（Supavisor）のセッションモードを経由する。TiDB より接続の設定が一段増える
- 無料枠のストレージは 500 MB（TiDB は 5 GiB）

調べきれていない点: Supabase の東京リージョンの有無、無料プロジェクトの一時停止の細かい条件。どちらも ADR には書かない。ただし、隣の Neon の項目は東京リージョンがないことを理由にしているので、Supabase は「東京リージョンの有無は理由にしていない」と 1 句足す。

`LEARNING_PLAN.md` は元の要望の記録なので、今回も変えない。

## 変更するファイル

### `docs/adr/0001-tidb-and-cloud-run.md`

「Considered Options」の Neon の項目の次に、次の 1 項目を足す。

```
- Supabase（PostgreSQL）: 課金されない点は同じだが、Free プランは DB へのアクセスが 1 週間ほどないとプロジェクトが一時停止され、復帰させるまで API が DB につながらない。学習のペースが空くと本番の DB が止まる。認証などの強みは API を Go で自作するこの計画では使わず、Cloud Run からの接続も共有プーラー（IPv4 用）を経由する分だけ設定が増える。東京リージョンの有無は理由にしていない
```

「Consequences」は変えない（決定そのものが変わらないため）。
